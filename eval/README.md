# 对照评估：用 skill 与不用 skill 的分析报告

## 设计

| 项 | 做法 |
|---|---|
| 问题 | 两个真实业务问题：Q1 老客召回优先级（RFM），Q2 新客复购与季度获客预算（同期群） |
| 对照组 | 同一模型的独立 subagent，拿到同样的问题和原始 CSV，**被禁止读取 skill 与本项目任何中间文件**，自由分析并写 HTML 报告（`baseline_q1/`、`baseline_q2/`） |
| 实验组 | 本项目 `outputs/run1_rfm`、`outputs/run2_cohort`（完整走 data-analysis skill 流程，含四角色审查） |
| 审稿 | 每题一个独立审稿 subagent，只拿到标成 A/B 的两份 HTML 与原始数据，按 [RUBRIC.md](RUBRIC.md) 从原始数据**独立复算** 12 个关键数字并打分；A/B 对应关系在 `.key.json`，审稿人被禁止读取；Q1 与 Q2 的 A/B 位置互换 |
| 汇总 | `python eval/summarize.py` → [results.md](results.md) |

## 结果

| 组别 | 平均准确率 | 平均可复算率 | 越权结论总数 | 陷阱识别 | 决策可用性 |
|---|---|---|---|---|---|
| 有 skill | 88% | 88% | **0** | 9/12 | 3.5 / 5 |
| 无 skill | 88% | 96% | **11** | 10/12 | 3.5 / 5 |

逐题明细见 [results.md](results.md)，审稿原文见 `audit_q1/audit.json`、`audit_q2/audit.json`。

## 怎么读这个结果

1. **数字准确率没有差别**（都是 88%）。两边的核心数字（同期群人数、复购率、集中度）都能被独立复算。skill 没有让模型「算得更准」。
2. **差别在于会不会说过头**。无 skill 的两份报告共 11 条越权结论：
   - 7 条因果越权，例如「180 天是回流的分水岭」「获客时点是主因」；
   - 3 条没有依据的精确数字，例如没有成本数据却给出「Q1 20% / Q2 35% / Q3 35% / Q4 10%」的预算比例；
   - 1 条小样本比率没有给区间。

   有 skill 的报告为 0 条。这部分来自四角色审查：Run 2 的 Reviewer 第一轮就阻断了一条同类预算建议。
3. **代价是可复算率略低、建议不那么直接**：
   - Q1 有 skill 的报告没写清 R 的打分方法和分层规则；Q2 没定义「圣诞品」。
   - Q1 的召回建议只给了筛选规则，没给排好序的名单；无 skill 的报告直接给了三档名单。
4. 陷阱识别两边接近。两份 skill 报告的正文都没提 sheet 重叠。无 skill 的 Q2 报告对左截断的处理比 skill 版更彻底，它用 2011 年数据重演、估了各月老客混入比例。

## 局限（请一并引用）

- **样本只有 2 个问题 × 2 组**，不足以做统计推断，只能当作案例对比。
- **盲审并不完全盲**：skill 渲染的报告带证据编号和「由 data-analysis skill 生成」字样，审稿人能认出来。审稿人声明两边用了同一套核查标准，但无法排除偏向。
- 对照组与实验组是同一个底座模型；实验组的分析者（主会话）比对照组投入了更多轮次，差异不能全部归因于 skill 本身。
- 审稿后我按审稿意见修改了 skill 报告：补了 R 打分与分层规则、圣诞品定义、sheet 重叠说明，并把「更好的筛选」改为「另一种筛选口径（未经回测）」。**上表分数来自修改前的版本**，没有重新评审。
